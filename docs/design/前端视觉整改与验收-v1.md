【整改清单】

UI-01：手机交互区域
上传、发送、关闭、侧栏、媒体动作及相关链接触摸命中至少44×44px；图标可保持20px。输入保留16px。波浪轨道扩大整体命中区，不改变6px横线／10px节距／28px峰值，也不把每条间距改成44px。
测试390／320px实际getBoundingClientRect及按钮可操作性，不只检查CSS字符串。

UI-02：精修弹窗
版本名称／v1为主，完整UUID进入按需详情；说明收敛为“另存新版，原版保留”。标题与操作区保持可见，中间内容可滚；明确指出缺少哪些必填项，而非只有一个灰色提交按钮。
原生dialog仍需实际测键盘首尾循环、Escape、焦点返回与长表单底部。静态截图按钮露出一部分不等于永久不可达，修复和报告必须准确。
不改变已确认版本的服务端约束，不因视觉简化让模型自报确认。

UI-03：信息层级
健康连接不常驻“重新连接”按钮；连接中断时明确显示恢复动作且不重放生成。型号、UUID和精确字节数放详情；保留AI视频／本地运镜非AI标签与可查询真实型号，不能隐藏模型回退。
卡片时长可显示实际值四舍五入，例如4.46秒；详情保留4.458333秒，不能改成请求4秒冒称精确输出。文件大小格式化为KB／MB，原始字节数仍可查。
“保存文案”操作靠近对应助手正文；同一作品若同时出现在任务和消息里，避免重复大图，但不能删除真实消息／任务事实。

UI-04：文字、配色与图标
正文15–16px，常规辅助信息至少12px；手机隐藏桌面Enter／Shift+Enter快捷键说明。以间距、字重与位置表达主次，不使用9px常驻提示。
主操作使用#506B83配白字（计算5.57:1），替代旧#607C95的普通白字按钮（4.36:1）。必要控件边界用#8292A2，装饰线保持#E3E8ED；焦点与必要图形≥3:1、正常文字≥4.5:1。禁用态另有语义与原因，不能套用正常可用对比度结论。
统一线性SVG图标，20px网格、约1.5–1.65px描边；品牌标识和已批准波峰保留。不要继续用多个字体字符模拟导航图标。

UI-05：完整状态与可恢复性
补齐按钮／输入的默认、悬停、按下、焦点、错误、禁用、提交中；媒体的加载、可用、已选参考、已确认首帧、失败／不可访问；任务的真实状态及对应动作。错误需有原因和下一步，不重复刷屏。
仅HTTP图片加载失败不能直接判定已删除；没有明确证据时使用“暂不可查看／重试读取”。
视觉模型报告中建议的“取消中／暂停”不能直接新增成媒体任务状态：run.stopping与task状态分开，必须以现有契约为准。已受理媒体不能假装可以取消。

UI-06：布局与原型一致性
保留冷白蓝灰、独立侧栏、对话主体，无常驻右参数栏。桌面／手机分别核对同滚动位置下的文字与媒体平衡，不能把自动滚到最新造成的截图上沿截断误判成图片拉伸。
竖图、横图、视频分开定义展示边界，保持原始比例和放大／下载通路；不要统一强裁横图。旧消息阅读期间图片加载、新回复与弹窗开合不能强拉到底。

UI-07：登录与手机可用性
模式切换应清晰，不重复放两个相同层级的登录入口；人工找回说明放对应流程，仍能发现帮助。抽屉、遮罩、长标题、键盘及减少动态效果按320／390px回归。
Mac／iOS软键盘和真机未实测时注明，不用Chrome手机视口模拟冒充真机验收。
