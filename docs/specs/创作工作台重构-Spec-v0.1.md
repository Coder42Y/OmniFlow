【一、目标、边界与已确认项】

▶ 产品目标〔已确认〕
G-01：以自然语言对话为主要入口，用户可以咨询、创作文案、生成图片、制作视频，再进入专业工作区精修。
G-02：适用商品、人物、场景与氛围等创作，不限定于电商；“视觉确认稿”不是模板商城。
G-03：Gemini 3.8 Flash 理解上下文并请求创作工具；服务端决定是否允许执行、创建任务并交付真实作品。
G-04：图片与视频在对话中直接展示／播放，提供下载、选择、修改与精修流转，不只回复“正在制作”。
G-05：支持 AI 动态视频与本地快速运镜，必须明确区分；不得把本地平移缩放冒充 AI 生成。
G-06：先以不超过 10 人的邀请内测建立单机可靠闭环，不新增独立云服务器预算。

▶ 已确认，不需再次选择
• 冷白蓝灰、克制简洁的视觉风格。
• 主导航与会话历史独立折叠；对话为中央主体，无常驻右侧参数栏。
• Codex 式左侧短横线、指针跟随波峰与定位交互，直接沿用已批准原型。
• 默认先出一张视觉确认稿，需要比较时再追加；没有参考图时不默认直接生成视频。
• 已明确参考图时默认首帧驱动；明确要求直接文生视频时保留直接路径。
• Gemini 3.8 Flash 作为主控；复用现有 agy 登录通路已被认可，不再要求给另一套 Gemini CLI 反复登录。
• Python + SQLite + 独立后台任务执行器；对话与精修共享任务／作品服务。
• 用户名＋密码，邀请注册，无邮箱／手机号；管理员由项目所有者持有。
• 人工核验身份后发一次性密码重置链接，由用户自行设密码并撤销旧登录。
• 用户原图与作品保留到主动删除；容量不足限制新增，不能静默清理旧作品。
• 当前开发机器继续承担内测后端；开发与内测需要隔离，具体部署细节尚待落实。
• 本轮真实生图和视频样片得到用户“its been good”的效果认可，无须重复确认这批样片。

▶ 不包含在当前批准范围
正式发布、开放公开注册、无限免费服务、收费模型回退、充值、主域名 DNS 迁移、把个人订阅视为已获多人服务许可。
Google 生图／视频备用仍是候选，不因为 Pro 登录或 agy 文本成功就自动启用。

【二、用户流程与作品行为】

▶ FR-01 咨询与生成区分〔已确认方向〕
“如何做视频”等咨询只回答，不自动消耗媒体额度。信息不足时只澄清必要内容，优先继承对话中已有的主体、画幅、时长、动作与参考版本。
用户明确要求生成时可进入执行，不强制对每个清晰指令重复弹确认框；服务端仍要校验归属、预算与支持能力。

▶ FR-02 生图与修改〔已确认方向；版本细则建议待批〕
默认生成一张；多方案需明确数量与额度。用户选择具体图片继续修改，结果另存版本，保留旧版；不覆盖已被视频引用的图片。
版本确认由用户操作或明确选择的对话事实产生，不能仅由模型输出 confirmed=true 认定。
首版图生图／局部修改的实际保真能力仍需单独实测，本轮真实测试只证明文生图成功。

▶ FR-03 视频默认路径〔已确认〕
1. 有明确参考图＋要求动态视频：绑定该图片版本，默认 keyframe 首帧驱动。
2. 没有图：先生成一张视觉确认稿；用户确认之后，再创建视频任务。
3. 用户明确要求直接文生视频：允许 text 路径，提前说明主体／文字一致性不保证。
4. 用户明确选择快速本地运镜：使用本地引擎，界面明确注明非 AI 动态生成。
5. 多张图片却没有明确目标：先补问，不使用“最后一张”“最新路径”等猜测替代选择。
6. 修改动作通常意味着基于同一参考图重新生成视频，不冒充对既有视频逐帧编辑；Flash 不支持的参考视频输入应明确拒绝。

▶ FR-04 版本、重试与停止〔建议待批〕
• 视频绑定创建时的参考版本，后续改图不自动替换既有任务输入。
• 用户主动“重新生成”创建新任务并说明额度；断线重连、重复点击与下载重试不能生成新副本。
• 尚未提交的任务可以取消并释放预留；供应商已受理的任务不承诺真正撤销或免计费，继续核对其终态。
• 停止文字输出与取消媒体任务分开处理，不因关闭聊天页面取消已受理的媒体任务。
• 暂不支持删除仍被执行中任务占用的输入版本，提示等待任务结束或先取消尚未提交的任务。

▶ FR-05 作品管理与历史〔建议待批，归属隔离为必须项〕
保留基本作品列表与按需打开的会话作品入口，支持查看、下载、引用、删除；不增加常驻第三栏。删除会话不默认连带删除作品；删除作品前展示影响。
旧 localStorage 会话不自动导入首个登录账号。建议首版不自动迁移，提供原记录导出／说明；有明确导入需求时再设计本人确认、数据校验与去重流程。

【三、界面基线】

▶ UI-01 对话页〔已确认方向；细部排布可在实现时复核〕
顶栏以会话标题、折叠入口、更多操作为主；输入区常驻输入、上传、发送。模型技术说明和画幅／时长等设置按需出现，不常驻堆叠。
作品按比例展示，与助手说明文字适当分离；不自动有声播放。真实排队、生成、保存、失败或待核对状态不能为追求简洁而隐藏。
用户正在阅读旧消息时，不因新消息或图片加载强行跳到底部。

▶ UI-02 左侧横线波浪导航〔已批准，必须保留〕
原型静态快照：assets/codex-wave-rail.approved.html。
SHA256：be8f15d9510bfb6a2bd937409c142fa7473876c17f901a7e495228ece1189448。
本次快照与已批准原型逐字节一致，原始 .superpowers 文件未改动；截图参考资源随快照归档，来源见 assets/README.md。
静止短线、局部渐长波峰、跟随与收回、消息预览、点击／拖动定位、活动标记、键盘导航均为验收基线。约 6px 静止宽、10px 间距、28px 峰宽来自项目已批准原型，不冒称 Codex 官方参数。
不得替换为圆点导航、常规滚动条或另起一版交互。

▶ UI-03 手机与可访问性〔已确认方向〕
手机单列对话、抽屉式侧栏；320px 与 390px 不横向溢出。关键动作不能只靠悬停，支持触摸、键盘与减少动态效果偏好。
服务器 Chrome 自动化已覆盖原型与本轮媒体播放；Mac Safari、iOS 真机及后台恢复仍需后续验收。

【四、首版范围与不做什么】

▶ 建议 P0〔待 D-01 确认〕
邀请注册与管理员基础操作；持久对话；图片上传、生成与版本引用；首帧／直接文本 AI 视频；明确标识的本地运镜；真实任务状态；基本作品列表和下载／删除。
精修采用轻量入口：文案修改；图片参数／描述调整后再生成；视频参考图／动作／画幅／时长调整后再生成。所有入口复用同一服务，不做另一套生成系统。

▶ 建议暂缓〔待 D-01 确认〕
高级时间线剪辑、多镜头自动成片、复杂音频包装、批量全案自动跑完、模板商城、组织协作、公开作品广场、计费充值系统。
现有直播分析、语音转写、片段裁剪等旧模块先保留源码和数据，不自动纳入此次 P0 重做与验收；是否保留用户可见入口须 D-01 统一确认，不静默删除功能。

【五、模型与供应商边界】

▶ MD-01 主控〔型号族已确认，档位待 D-02〕
必须显式指定 gemini-3.8-flash-low / medium / high 中获批的具体 ID，不用 auto / flash 别名，不在失败时偷偷改为其他模型。
当前 low 已通过文字、典型流程决策及真实媒体工具调用。建议首版默认 low，按需另测 medium，不常驻模型下拉框；最终默认档位未获批。
授权复用优先使用 /usr/local/bin/agy 原入口，不绕过启动脚本直接执行底层二进制。不得提取其 OAuth token 自行请求内部服务。
供应商登录缓存与网站用户登录会话是两回事：网站会话过期，不应清除主控提供方的授权。

▶ MD-02 媒体路由〔已确认〕
图：Agnes Image 2.5 Flash。
AI 视频：Agnes Video 2.5 Flash，已核对现行约束为 720P 档、4–12 秒、n=1；新增参数须按能力表验证。
本地视频：独立标识的 FFmpeg 运镜路径。
Google Nano Banana 生图、Google 视频只保留候选位置，官方接口可用性、实际账户权益及费用未核验前禁用自动切换。

▶ MD-03 免费与失败策略〔已确认方向，账户级保险待核验〕
免费优惠到期时暂停新的 AI 视频任务并提示，已完成作品可继续访问。区别周期额度用尽、免费活动结束、网络故障与账户问题。
公开价格快照不是账户账单凭证。上线前需核实账户额度、免费活动状态与可用的费用上限；不能确认免费时暂停新增提交，不通过调用收费模型探测是否免费。
不因配置本地额度就声称增加了供应商额度。媒体模式或主控模型不可用时明确报错，不用假结果或不披露的备用模型保持“成功率”。

【六、系统架构与工具协议】

▶ AR-01 已确认的结构
浏览器 → 身份／对话 API → Gemini 主控适配器 → 受控创作工具网关 → 任务服务 → 独立 worker → 媒体供应商。
SQLite 保存用户、消息、任务、作品元数据与额度事实；媒体文件位于仓库和静态根目录之外。
文字流是展示方式，不控制是否执行媒体分支。页面断开不决定任务生死，刷新从服务端恢复。

▶ AR-02 实现建议〔工程建议待整体评审，不要求用户逐项选框架〕
后端建议 FastAPI + SQLite（开启外键、短事务、WAL 与明确 busy timeout）+ 独立 Python worker；不首发引入 Redis 或多机队列。
前端建议沿用 Vue 3，改为构建产物与按职责拆分的组件，不因为换视觉而强制重写为 React；Vite 等构建细节留给实施计划。
worker 通过数据库租约领取任务，领取与提交意图可追踪；网络请求期间不长时间持有写事务。
现有 FFmpeg 运镜、媒体探测与 Range 播放能力可审计后复用，不直接沿用无鉴权的全目录静态服务。

▶ AR-03 建议工具契约
• submit_image：prompt、画幅、可选的自有参考版本、明确数量。
• submit_video：prompt、模式、参考版本、请求时长和画幅。
• submit_local_motion：自有图片版本、允许的运镜类型与输出参数。
• read_task / list_artifacts：只读当前授权范围内的状态与作品。
所有工具使用固定 schema、拒绝额外参数；供应商模型由服务端路由，不允许模型传任意 base_url、shell、文件路径或密钥。
user_id、session_id、动作额度及幂等标识来自可信的服务端上下文，不由模型自行声称。工具即使知道其他作品 ID 也必须通过归属验证。
输出 task_id、真实状态、最终 artifact_version_id 或稳定错误码。工具先返回任务已受理，不在收到供应商完成及文件落盘之前报“已生成”。
MCP 是已实测可行的接入机制，不把本轮仅限两个槽位的测试服务当作生产实现。

▶ AR-04 结果与事件
展示文字与执行结果分离。若使用 agy --json-schema，读取并校验 structured_output；不得从夹杂代码块、说明或内部字段的 response 中任意截取 JSON 执行。
建议事件类型：message.delta、message.completed、task.updated、artifact.ready、error；带稳定 event_id / conversation_id，重连去重并以数据库终态为准。
SSE 或等效机制由实施计划落实，流中断允许退回状态查询，不回退到“只有文字没任务”的旧分支。

▶ AR-05 隔离要求〔上线必须，具体实现待核验〕
网站用户不得获得宿主机任意文件、终端、浏览器、全局其他 MCP 或个人历史对话访问权。
本轮已证明三个精确 MCP allow-rule 可以放行媒体功能；不证明整个 agy Agent 已安全隔离。
正式接入需独立运行环境、最小工具权限、受控上下文与每用户／每会话隔离；不能每次请求都修改所有者共享配置，也不能使用 --dangerously-skip-permissions。
在真实凭据环境完成权限边界前，不用恶意提示词对完整宿主 Agent 做无隔离试验。

【七、数据、任务、额度与删除】

▶ DA-01 建议数据模型
users；invites；login_sessions；password_reset_tokens；conversations；messages；tasks；artifacts；artifact_versions；message_artifacts；quota_ledger；audit_events。
使用独立内部 ID。任务和作品均记录 owner_id；版本不可变，消息只引用版本 ID，不复制媒体二进制。
关键约束：规范化用户名唯一；邀请／重置一次性消费；消息顺序稳定；请求幂等键唯一；额度预留有唯一关联；输入版本归属正确；供应商任务 ID 和操作时间可追踪。
具体 SQL、索引与迁移脚本在实施计划中落实，不把概念表名当作已建数据库。

▶ DA-02 任务状态机〔建议规范，可靠性方向已确认〕
queued → submitting → running → saving → completed。
另含 failed、canceled、submission_unknown、needs_reconciliation。
• queued：数据库已持久保存，额度预留成功。
• submitting：先记提交意图，再调用供应商。
• running：已有可核对的供应商任务 ID，允许重启续查。
• saving：供应商生成完成，正在下载／验证／落盘；此阶段失败重取同一结果。
• completed：文件存在且基础校验通过，作品关联写入数据库。
• submission_unknown：请求可能已被受理但未取得可靠 ID，不盲目再次 POST。
• needs_reconciliation：保留证据等待查明，不伪造失败退款或成功结果。
不要声称跨数据库与外部 API 已实现严格 exactly-once。幂等约束和不重提规则减少重复，不消除所有不确定性。

▶ DA-03 额度〔方案待 D-03〕
图片按请求张数、视频按请求秒数预留；文本按用户请求计数并另设长度／模型调用保护。用户请求次数不等于 CLI 内部模型请求次数，需分别观测。
同一事务处理任务和额度预留；重复点击／客户端重试复用原任务，不重复计额。
只有确定未受理，或明确无供应商消耗时释放预留；不确定状态待核对。下载重试不再计生成额度；用户主动重新生成是新任务。
每用户与全站上限同时生效，较低的供应商剩余额度优先约束；不承诺每人都能同时耗尽个人上限。

▶ DA-04 保留与删除〔保留原则已确认，具体时限待 D-05〕
作品与原图不按年龄自动删除；临时缓存独立管理，不把唯一原图或生成结果误归为缓存。
删除作品立即撤销应用访问和供应商临时取图授权；建议在线文件在 24 小时内清理，备份副本按到期策略清除，最长 28 天。不能承诺已经送达外部供应商的内容会即时被其清除。
删除记录单独保留到相关备份过期，恢复备份时重新应用删除与账号撤销事实，避免“恢复后被删除作品重新出现”。
容量不足先阻止新上传／生成并提示，不静默清理已有作品。

【八、账号、隐私与安全】

▶ SE-01 已确认的账号职责
普通用户只访问自己的对话、任务与作品；管理员管理邀请、停用、人工核验后的重置、故障与用量概况。
管理员产品界面不提供浏览他人私密聊天／作品的入口；这不是端到端加密，也不阻止服务器所有者直接接触磁盘。
首位管理员建议通过本地一次性创建命令建立，不提供默认密码，不把第一个注册者自动提权。

▶ SE-02 建议安全默认值〔待 D-05〕
邀请单次使用、7 天有效、可撤销；重置链接单次使用、30 分钟有效；网站登录会话最长 7 天，可主动注销／撤销，重置密码或停用时撤销旧登录。
用户名建议 3–32 位字母／数字／下划线，规范化为小写；若需要中文登录名需明确调整。密码建议 12–128 字符，使用 Argon2id 校验值，不记明文或可还原密码。
凭据只存摘要；注册和邀请消费同一事务。不要仅凭报出用户名就重置密码；人工核验通过已有可信联系渠道完成。

▶ SE-03 不可省略的工程控制
HTTPS；HttpOnly、Secure、适当 SameSite Cookie；CSRF 防护；登录／邀请／重置／任务接口限速；账户停用与会话撤销即时生效。
每次查询、下载、修改、删除都检查归属，不能只在前端隐藏按钮。媒体 Range 和 HEAD 同样鉴权；供应商取图采用绑定文件／任务的短期权限，不公开整个上传目录。
输入尺寸／类型校验、解码验证、文件路径归一化、结果下载的网络目的地限制；禁止 URL 参数绕入本机网络。
日志不记录密码、供应商凭据、一次性授权链接或完整私密内容；记录 task_id、耗时、错误类别和必要审计。
内测用户需获知其文本／参考图会送达选定供应商，明确删除及第三方保留的边界。

▶ OP-04 备份建议〔待 D-04〕

目标 RPO 24 小时（最多丢一天新数据），目标 RTO 4 小时（机器可用、备份可达时）；整机损坏或外网停机不承诺 4 小时恢复。
优先已有常开 NAS／第二台机器；Mac 可作为候选，但休眠或离线会影响日备份目标。具体设备、目录、空间与加密密钥保管方式仍需确认，不要求用户在聊天中提供密码。
首次对外内测前必须做一次隔离恢复演练，并验证删除作品／停用账号不会恢复可见；同机复制文件不能冒充异机备份。

【十一、与实际代码、旧 Spec 的差异】

以下以当前 worktree 的实际源代码为依据，不声称线上故障已全部复现：
1. index.html:1391、1410 使用 localStorage 保存聊天；目标要求账号归属的服务端持久会话。现状不是已完成多用户历史恢复。
2. index.html:1681 发 stream:true；server.py:1516、1589、1694 的媒体分支排除流式请求。此前隔离测试已观察到绕过生成，但本轮未修复、未做生产 E2E。新方案必须统一流式与任务创建。
3. server.py:953 的 _call_agy_cli 已有 agy 调用，但未显式指定模型；server.py:1447 起的主控包装失败后回退 Agnes，却仍使用 Gemini 主控标识。新方案要求固定模型和真实来源，禁止此不透明回退。
4. server.py:1109 的视频接口实际调用 generate_motion_video；旧别名也路由至本地运镜。函数注释或测试中的“Agnes Video Engine”名称不证明已对接真实 Agnes 视频 API。新 MCP 独立实测不能冒充这个正式接口已改好。
5. server.py:121 起以 WORKSPACE_DIR 做静态根目录，含通配跨域头和无用户归属校验的媒体访问；新方案要求受保护媒体、最小静态根与完整鉴权。这里是代码层风险判断，不表示已进行线上敏感文件读取测试。
6. 现有 http.server / ThreadingHTTPServer、单文件 Vue 页面、requests / urllib3 依赖不等于拟议 FastAPI、SQLite、worker 已实现。新框架与数据迁移是新增工作。
7. 旧 Spec 以电商全案并行生成、Agnes 主文本、本地运镜默认、真实视频预留和用户配置供应商凭据为主；最新确认改为通用创作、Gemini 主控、视觉确认后首帧视频、明确本地运镜分流、管理员持有后端凭据。
8. 旧测试有生成真实文件／播放检查，但不能替代新登录隔离、免费策略、工具授权、数据库恢复和身份迁移验收。
